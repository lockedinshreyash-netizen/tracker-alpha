# The Play app

Tracker Alpha on Google Play is this website in a **Trusted Web Activity**:
real Chrome with its address bar removed, in sticky immersive full screen (no
status bar, no navigation bar), launched from a 1.4 MB Android shell. The site
is the app, so **a Vercel deploy updates the Play app instantly**. A new
`.aab` is only needed when something here changes: name, icon, colours,
display mode, or the yearly Play target-SDK bump.

| | |
|---|---|
| Package | `in.trackeralpha.app` (permanent once uploaded) |
| Opens | `https://trackeralpha.in/?source=android-app` |
| Display | `fullscreen-sticky` → Android sticky immersive |
| SDK | min 24, target/compile 36 |
| Generated by | Bubblewrap 1.27.0, from `twa-manifest.json` |

## Files

- `twa-manifest.json` is the source of truth. Everything under `app/` is
  generated from it.
- `upload.keystore` + `signing.local.json` hold the **upload key** and its
  password. Both are gitignored. **Back both up to a password manager now.**
  If they are lost: Play Console → Test and release → App integrity → Upload
  key → *Request upload key reset*.
- `../public/.well-known/assetlinks.json` is what removes Chrome's address
  bar. It is written by `npm run android:fingerprint`; don't edit it by hand.

## Build

```bash
npm run android:build
```

The build writes `app-release-bundle.aab` (upload this) and
`app-release-signed.apk` (sideload this to test). It needs
`~/.bubblewrap/config.json` pointing at JDK 17 and the Android SDK; both are
set up on this Mac.

## First release

1. **Deploy the site.** `/.well-known/assetlinks.json` and
   `/icon-monochrome.png` must be live. Check:

   ```bash
   curl -sI https://trackeralpha.in/.well-known/assetlinks.json
   ```

   It must be `200` and `content-type: application/json`, with no redirect.
2. **Test the sideloaded build.** `adb install app-release-signed.apk`
   (adb is in `~/.bubblewrap/android_sdk/platform-tools`), or copy the file to
   the phone. It is signed with the upload key, which `assetlinks.json` already
   trusts, so it should open with **no address bar**.
3. **Run `supabase/account.sql`** in the Supabase SQL editor, or the in-app
   *Delete account* button answers "isn't switched on yet".
4. **Create the app** in Play Console with package `in.trackeralpha.app`, and
   upload `app-release-bundle.aab` to **Closed testing**. Play App Signing is
   automatic: Google re-signs every install with *its own* key.
5. **Trust Google's key.** This is the step that, if skipped, leaves Play
   installs showing the address bar. Play Console → Test and release → App
   integrity → App signing → copy the **App signing key certificate**
   SHA-256 (not the upload key's), then run this with the fingerprint pasted
   over `PASTE_SHA256_HERE`. It is 32 pairs like `8F:1A:43:…:4B`; keep the
   quotes. Angle brackets (`<SHA-256>`) would break here: zsh reads `<` as
   "read from a file".

   ```bash
   npm run android:fingerprint -- 'PASTE_SHA256_HERE' "Play app signing key"
   ```

   Deploy the site again.
6. **Store listing URLs.** Privacy policy: `https://trackeralpha.in/privacy/`.
   Data safety → account deletion URL: `https://trackeralpha.in/delete-account/`.
7. **Closed testing gate.** New personal developer accounts need 12 testers
   opted in for 14 continuous days before Production unlocks. Start
   recruiting now; this is the long pole, not the build.

## Later releases

Change `twa-manifest.json`, then run `npm run android:build`. Bubblewrap sees
the change, offers to update the project, and bumps `appVersionCode`. Say
yes: Play rejects a version code it has seen before.

## Still showing an address bar?

- Fingerprint: Play installs need the **App signing** key's SHA-256 (step 4).
  The upload key's only covers sideloaded builds.
- Chrome caches the verification. On the phone: Settings → Apps → Chrome →
  Storage → **Clear data** (clearing the cache is not enough), then reopen.
- Ask Google directly:

  ```bash
  curl -s "https://digitalassetlinks.googleapis.com/v1/statements:list?source.web.site=https://trackeralpha.in&relation=delegate_permission/common.handle_all_urls"
  ```

- The bar *will* appear while signing in with Google. The flow leaves
  trackeralpha.in for Google's and Supabase's domains, and a TWA always shows
  the address of a site it can't vouch for. It disappears on return.

## Toolchain notes (this Mac)

- JDK 17 is Homebrew `openjdk@17`. The SDK is `~/.bubblewrap/android_sdk`
  (cmdline-tools 23, platform 36, build-tools 36.1.0). `android_sdk/bin` is a
  symlink to `cmdline-tools/latest/bin`, because Bubblewrap only recognises
  the pre-2021 SDK layout.
- Java on this network cannot connect to `release-assets.githubusercontent.com`
  (curl can), so the Gradle wrapper's first download failed. Gradle 8.11.1 was
  fetched with curl into `~/.gradle/wrapper/dists/`. If a future Gradle
  version fails the same way, do the same: download the
  `services.gradle.org/distributions/gradle-X-bin.zip` URL and verify it
  against its `.sha256`.
